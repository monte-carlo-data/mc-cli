Monte Carlo reads Snowflake through a connection. A connection joins two things: a warehouse, the Monte Carlo object that sets which deployment the queries run through, and credentials, which hold the Snowflake key pair. One command creates all three, or you can create them one at a time.

Before you start

  • A Snowflake user for Monte Carlo, with a key pair and the grants Monte Carlo needs. See Snowflake in the Monte Carlo docs. A key pair is the only authentication Snowflake credentials take.
  • Credentials for the CLI. See OAuth client or API token.
  • The deployment the queries run through. Monte Carlo hosts one for your account; a collection agent you run in your own cloud has one too. Find its id with:
montecarlo deployments list

In one step

Check the key pair first. This runs the validations from the deployment and creates nothing:

montecarlo connections add snowflake --deployment-id <deployment_id> --account <account> --user <user> --private-key @<path> --validate-only

Then add the connection. It validates again, asks you to confirm, and then creates the warehouse, the credentials and the connection:

montecarlo connections add snowflake --name <name> --deployment-id <deployment_id> --account <account> --user <user> --private-key @<path>

If a step fails, or you interrupt it, what it created is deleted again. --yes answers the question, and is required without a terminal. To add the connection to a warehouse you already have, pass --warehouse-id instead of --deployment-id.

  • --account is the account identifier without .snowflakecomputing.com, such as xy12345.us-east-1.
  • --private-key is the PEM text, BEGIN and END lines included. @<path> reads it from a file, and --private-key-prompt asks for it instead. For an encrypted key, add --private-key-passphrase-prompt.
  • --warehouse is the Snowflake virtual warehouse the queries run in, not the Monte Carlo warehouse. Without it, the user's default is used.

See montecarlo connections add snowflake for every option.

Step by step

To create each part yourself, for example to reuse a warehouse or credentials, run these in order. Each prints the id the next one needs; -o json makes them easy to read from a script.

  1. Create the warehouse on the deployment: 
    montecarlo warehouses create --name <name> --deployment-id <deployment_id> --type snowflake
  2. Check the key pair from the deployment: 
    montecarlo credentials validate snowflake --deployment-id <deployment_id> --account <account> --user <user> --private-key @<path>
  3. Store it: 
    montecarlo credentials create snowflake --account <account> --user <user> --private-key @<path>
  4. Join the warehouse and the credentials in a connection: 
    montecarlo connections create --name <name> --warehouse-id <warehouse_id> --credentials-id <credentials_id>
  5. Check the connection: 
    montecarlo connections validate <connection_id>
