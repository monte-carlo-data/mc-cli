A profile is a named set of credentials in ~/.mcd/profiles.ini, the file every Monte Carlo tool shares. With one profile per account or environment, you can switch between them without passing credentials each time.

Add a profile

Write each profile with configure or profile set, naming it with --profile or as the argument. The OAuth client and API token guides cover both commands.

montecarlo configure --profile staging
montecarlo profile set prod --api-id <id> --api-token @<path>

The first profile you write becomes the active one.

Switch between profiles

List the profiles and see which one is active:

montecarlo profile list

Make another one active. The choice is stored in ~/.mcd/cli.ini, and every command uses it from then on:

montecarlo profile use staging

Or use a profile for one command only:

montecarlo whoami --profile prod

Which credentials a command uses

Credentials come from the first of these that has them:

  1. The credential flags, such as --api-id and --api-token.
  2. The MCD_DEFAULT_* environment variables, such as MCD_DEFAULT_API_ID and MCD_DEFAULT_API_TOKEN.
  3. A profile: the one --profile names, else MCD_DEFAULT_PROFILE, else the one chosen with profile use, else default.

Credentials resolve as a set: pass a complete API token pair or OAuth client, or none. The Terraform provider reads MCD_DEFAULT_PROFILE but not the profile use choice, so set the variable when a script runs both.

--config-dir reads profiles.ini and cli.ini from another directory instead of ~/.mcd, which keeps a script or a test away from your own profiles.
