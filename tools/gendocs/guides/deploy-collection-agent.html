A deployment is where Monte Carlo's queries against your data run. Monte Carlo hosts one for your account. To keep that traffic in your own cloud, create a deployment and register one of these on it:

  • A collection agent: a service in your cloud that runs Monte Carlo's queries and sends back the results. It runs on AWS, Azure or GCP, or anywhere as a generic agent.
  • A data store: a bucket or container in your cloud where Monte Carlo keeps what it collects, while it connects to your warehouse directly. It can be an S3 bucket, an Azure blob container or a Cloud Storage bucket.

Each takes three steps: create the deployment, build the agent or data store in your cloud, and register it. The CLI does the first and the last. Deployments in the Monte Carlo docs compares the options.

Create the deployment

--type is COLLECTION_AGENT or COLLECTION_DATA_STORE, and --runtime-platform is AWS, AZURE, GCP, or GENERIC for an agent you run anywhere:

montecarlo deployments create --type COLLECTION_AGENT --runtime-platform AWS --name <name>

On AWS, the output includes aws_external_id. The role Monte Carlo assumes has to trust it, so build the agent after this step. Read it again at any time with:

montecarlo deployments get <deployment_id>

Register a collection agent

Registering checks the agent before enabling it. If the check fails, nothing is registered; fix the cause and run the command again.

AWS

Build the agent with the mcd-agent AWS module, passing it the external id. Then register its Lambda function and the role Monte Carlo assumes:

montecarlo collection-agents register aws --deployment-id <deployment_id> --lambda-function-arn <function_arn> --role-arn <role_arn>

Azure

Build the agent with the mcd-agent Azure module. Monte Carlo calls it with the function app key, or with a service principal, which needs the Cloud Application Administrator role in your tenant to set up. Choose before you build it; Azure: Agent Deployment has the details. With the function app key:

montecarlo collection-agents register azure --deployment-id <deployment_id> --function-app-url <url> --authentication-type AZURE_FUNCTION_APP_KEY --function-app-key-app-key-prompt

With a service principal, pass --authentication-type AZURE_FUNCTION_SERVICE_PRINCIPAL and the --service-principal-* flags instead. See collection-agents register azure.

GCP

Build the agent with the mcd-agent GCP module, then register its Cloud Run service with the key of the service account Monte Carlo calls it as:

montecarlo collection-agents register gcp --deployment-id <deployment_id> --cloud-run-url <url> --authentication-type GCP_JSON_SERVICE_ACCOUNT_KEY --service-account-key @<path>

Generic

A generic agent runs anywhere and connects out to Monte Carlo, so it needs a credential before it starts. Create an OAuth client for it, or a token with create generic-token. The secret is shown only once:

montecarlo collection-agents create generic-oauth-client --deployment-id <deployment_id>

Run the agent with that credential, for example on Kubernetes with the mcd-k8s-agent module, or as Generic Agent Deployment describes. Then register it. Until the agent has connected, the command waits and retries for up to five minutes:

montecarlo collection-agents register generic --deployment-id <deployment_id>

Register a data store

Create the deployment with --type COLLECTION_DATA_STORE, then create the bucket or container, and access for Monte Carlo to it, yourself. Registering writes a test object and reads it back before enabling the data store.

On AWS, the role has to trust the deployment's external id and Monte Carlo's AWS account, shown as the AWS account ID under Collection on the Account Information page in Monte Carlo. AWS: Data Store Deployment has the details.

montecarlo collection-data-stores register aws --deployment-id <deployment_id> --bucket-name <bucket> --role-arn <role_arn>

On Azure, with the storage account's connection string. See Azure: Data Store Deployment:

montecarlo collection-data-stores register azure --deployment-id <deployment_id> --container-name <container> --authentication-type AZURE_STORAGE_ACCOUNT_KEYS --storage-account-keys-connection-string-prompt

On GCP, with a key for a service account that can use the bucket:

montecarlo collection-data-stores register gcp --deployment-id <deployment_id> --bucket-name <bucket> --service-account-key @<path>

Check it

The deployment is enabled once an agent or a data store is registered on it:

montecarlo deployments get <deployment_id>

Then connect a warehouse through it, as in Connect a Snowflake warehouse. An agent you run can also read connection credentials from your own secret store; see Keep connection credentials in your own secret store.
