Monte Carlo normally keeps a connection's credentials. With self-hosted credentials, the secret stays in your own store: Monte Carlo keeps only where to find it, and your collection agent reads it each time the connection runs.

Before you start

  • A collection agent you run, registered on the deployment the warehouse uses. The deployment Monte Carlo hosts has no agent of yours to read the secret.
  • The secret, holding the JSON the connection type expects. Self Hosted Credentials with the Agent has the shape for each type. For Snowflake, private_key is the base64 body of the PKCS#8 key, without its BEGIN and END lines.
  • Read access for the agent to that one secret: an IAM policy on AWS, the Key Vault Secrets User role on Azure, or roles/secretmanager.secretAccessor on GCP. An environment variable has to be set in the agent's runtime, and a file has to exist there.

Where the secret can be

AWS Secrets Manager--self-hosted-aws-secret, with --self-hosted-aws-region and, to read it through another role, --self-hosted-aws-assumable-role and --self-hosted-aws-external-id
Azure Key Vault--self-hosted-azure-akv-secret, with --self-hosted-azure-akv-vault-name or --self-hosted-azure-akv-vault-url
GCP Secret Manager--self-hosted-gcp-secret
Environment variable--self-hosted-env-var-name, a name starting with MCD_, with --self-hosted-env-var-kms-key-id if the value is encrypted with AWS KMS
File--self-hosted-file-path, the path on the agent

Add a connection

connections add takes one of these sets of flags instead of the secret itself. Check that the agent can read the secret and connect with it; this creates nothing:

montecarlo connections add snowflake --deployment-id <deployment_id> --self-hosted-aws-secret <secret> --validate-only

Then add the connection. As in Connect a Snowflake warehouse, it validates again, asks you to confirm, and creates the warehouse, the credentials and the connection:

montecarlo connections add snowflake --name <name> --deployment-id <deployment_id> --self-hosted-aws-secret <secret>

Any other connection type works the same way: montecarlo connections add <connection-type>, with one set of --self-hosted-* flags.

Step by step

To create the credentials yourself, name the connection type they're for. The flags drop the --self-hosted- prefix, as in --aws-secret.

  1. Check them from the deployment: 
    montecarlo credentials validate aws-secrets-manager --deployment-id <deployment_id> --connection-type snowflake --aws-secret <secret>
  2. Store them: 
    montecarlo credentials create aws-secrets-manager --connection-type snowflake --aws-secret <secret>
  3. Use them in a connection: 
    montecarlo connections create --name <name> --warehouse-id <warehouse_id> --credentials-id <credentials_id>

The other stores are azure-key-vault, gcp-secret-manager, env-var and file, under both credentials validate and credentials create.

To move an existing connection to self-hosted credentials, delete it and add it again with them.
